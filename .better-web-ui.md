# Warehouse UI Design Context

## Design Context

### Users
KMJ Optical owners and warehouse staff, primarily on phones while standing at the counter or moving around the shop. They need to check lens stock, add lens pairs to a cart, withdraw stock, create purchase demands, and review history quickly with one hand.

### Brand Personality
Warm, editorial, tactile, and quietly premium. The warehouse should feel like a well-run optical house: cream paper, ink, terracotta, a serif voice for headings, and calm utility for daily work. Never like a generic desktop admin dashboard squeezed onto a phone.

### Aesthetic Direction
Warm Eyewear Editorial. Cream and ink neutrals, terracotta accent, sage highlight, large Fraunces display type, Manrope body text, IBM Plex Mono for small labels and numbers. Dark, high-contrast hero panels; soft orbs on the login shell; 20-24px card radii; shelf dock with the active tab lifting like a paper tab. Motion stays physical but subtle: icon selection pops, cart-count bumps, indicator draws, spring-like press feedback, route fades, staggered list entrances, and the signature water-wave theme reveal. Light and dark mode both matter.

Anti-references: dense desktop tables on mobile, cold blue-gray dashboards, generic SaaS card grids, neon/glassmorphism excess, noisy decorative gradients, childish illustration, and animation that delays the task.

### Implementation Defaults
- React 18, Vite, React Router, Tailwind CSS, CSS custom-property design tokens.
- Final direction is Editorial, scoped by `[data-design='editorial']` with editorial values also on `:root` as the fallback.
- Typography: Fraunces display, Manrope body, IBM Plex Mono for small uppercase labels and figures.
- Final dock is Shelf: five labeled tabs (Home, Stock, Cart, History, More) with the active tab lifting as a paper tab.
- Existing `th-*` token system and shared component primitives are the baseline.
- Native CSS motion only; do not add an animation dependency for this pass.
- Minimum 44px touch targets, safe-area support, and full `prefers-reduced-motion` fallbacks.
- Keep existing data fetching, business logic, and routes unchanged unless a visual change requires it.

### Design Principles
1. Make the phone the primary canvas; desktop is the adaptation, not the reverse.
2. Lead with editorial hierarchy: serif page titles and hero copy, sans body, mono micro-labels.
3. Keep five labeled tabs with visible 10px labels; labels remain the primary identification aid for low-literacy users.
4. Reserve terracotta for action and current state; keep the shell warm and neutral, with sage as a secondary highlight.
5. Every touch gets immediate feedback, but routine motion stays under 300ms; the theme reveal is the one deliberate exception.
6. Motion must clarify navigation and depth; never animate for decoration alone. Dock motion is limited to icon selection pops, cart-count bumps, indicator draws, and press feedback. Avoid oversized or continuously animated navigation chrome.
